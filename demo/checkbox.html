Attribute

The Accesserty UI Kit checkbox attributes:
Name Description
name Submission key. Multiple checked controls with the same name produce multiple entries; an unnamed control produces none.
value Value submitted when checked (default on). An explicit empty string remains empty.
checked checkbox checked
disabled checkbox disabled
label Fallback visible label text when no slotted label is supplied.
aria-label Accessible name passed to the internal checkbox input.
aria-labelledby Label IDs resolved in the containing document or shadow root, including late and replaced labels.
aria-describedby / aria-invalid Connect visible help/error text and expose application validation state.
required Require this individual checkbox to be checked. This does not express “at least one of a group”.

Properties

JavaScript properties on <au-checkbox>:
Property Type Description
name / value / requiredstring / string / booleanWritable reflected properties; updates synchronize native submission and validity.
checked boolean (getter + setter) Get or set the checked state. Setting to false removes the checked attribute — React-safe.
disabled boolean (getter + setter) Get or set the disabled state. Setting to false removes the disabled attribute — React-safe. 
const cb = document.querySelector('au-checkbox');
cb.checked = true;   // sets attribute
cb.checked = false;  // removes attribute
cb.disabled = true;

Reset restores the checked state at first connection, not always unchecked. Assignments, reset and state restoration are silent. Disabled ancestor fieldsets prevent interaction and submission. The current checked state is reflected on the host; this attribute is not a native-style defaultChecked API.

focus(options) focuses the checkbox. Native labels associated with the host can name and activate it when no internal label is supplied. Explicit aria-labelledby takes precedence in browsers with element-reference support; older engines use plain text and should receive an explicit localized aria-label for rich labels. Do not place interactive elements inside the label slot.

Vue/Nuxt: use :checked="agreed" @change="agreed = $event.detail", not direct text-style v-model. React can bind checked and onchange. Angular form directives need a value accessor; template property/event binding is separate. Register components only on the client in SSR apps.

Events

Events dispatched by <au-checkbox>:
Event Detail Description
change boolean (checked state) One event after user activation, with boolean detail. Bubbles and is composed. Property assignment is silent.
input—Native composed event; the submitted value is already synchronized when listeners receive it.
focus — Native focus event, not a synthetic duplicate. Composed but does not bubble; use focusin for delegation.
blur — Native blur event, not a synthetic duplicate. Composed but does not bubble; use focusout for delegation. 
document.querySelector('au-checkbox').addEventListener('change', (e) => {
  console.log('Checked:', e.detail); // true | false
});

FAQ

How does it compare to native checkboxes?

Prefer a native checkbox when it meets your needs. This component adds a configurable label/style and form contract, not a guarantee of screen-reader or WCAG conformance. Keep a visible label, verify custom theme contrast and target size, and test the consuming page with assistive technology.

Use a fieldset and legend to name a related group. A rule such as “choose at least one” needs group-level application validation rather than setting required on every checkbox.

Accesserty UI Kit Switch

Attribute

The Accesserty UI Kit Switch attributes:
Name Description
name Form field name (used for form submission)
value Value submitted when the switch is on (default: on)
checked Sets switch to on state by default
disabled Disables the switch
off Set "off" text label
on Set "on" text label
label Fallback visible label text when no slotted label is supplied.
aria-label Accessible name passed to the internal switch input.
aria-labelledby Label IDs resolved in the containing document or shadow root; late and replaced references are tracked.
aria-describedby / aria-invalid Connect application help/error messages and validation state.
requiredNative validation requires this switch to be on.

Properties

JavaScript properties on <au-switch>:
Property Type Description
name / value / requiredstring / string / booleanWritable reflected properties; a missing value defaults to on, while an explicit empty value remains empty.
checked boolean (getter + setter) Get or set the switch on/off state. Setting to false removes the checked attribute — React-safe.
disabled boolean (getter + setter) Get or set the disabled state. 
const sw = document.querySelector('au-switch');
sw.checked = true;   // turns on
sw.checked = false;  // turns off
console.log(sw.checked); // boolean

Programmatic changes synchronize the native checked state, switch ARIA state, validity and submitted value. User activation also reflects checked on the host. Reset silently restores the state captured at first connection; it does not always turn the switch off. Disabled ancestor fieldsets prevent interaction and submission.

Use focus(options) to focus the internal switch. Native host-associated labels name and activate it when no internal label is supplied. Older engines use plain-text reference fallbacks; supply a localized aria-label for rich labels there. Avoid interactive content inside the label slot.

Vue/Nuxt: bind :checked="enabled" @change="enabled = $event.detail", not text-style v-model. React supports checked/property and onchange binding. Angular form directives need a value accessor beyond custom-element schema configuration. SSR fixtures verify client registration after server-rendered hosts, not server-rendered shadow controls.

Events

Events dispatched by <au-switch>:
Event Detail Description
change boolean (checked state) One event when the user toggles the switch. Bubbles and is composed. Assignment, reset and state restoration are silent. 
document.querySelector('au-switch').addEventListener('change', (e) => {
  console.log('Switch is now:', e.detail ? 'On' : 'Off');
});

FAQ

Why use input[type="checkbox"] instead of creating everything with div elements?

The native checkbox supplies keyboard and form-control behavior. Its switch role and mirrored aria-checked expose on/off semantics. Keep the accessible label stable when toggling; off/on text is decorative and hidden from assistive technology. Native behavior and automated tests do not establish full screen-reader conformance.

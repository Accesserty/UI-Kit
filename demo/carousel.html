Accesserty UI Kit — Carousel

<au-carousel> is a Web Component. You provide the slide blocks as native HTML children (each may contain links or buttons); the component supplies a real button per block for pagination — named by the block's title — a responsive slides-per-view driven by @container, prev/next buttons, a polite live region and roving keyboard focus. Tab order is pagination → content → prev/next.

Resize the window: slides-per-view steps 1 → 2 → 3 based on the carousel's own width (@container, not the viewport). All slides stay readable and reachable — a keyboard or screen-reader user can move through every block freely; tabbing to an off-screen slide just scrolls it into view.

Basic usage

<au-carousel>
  <div data-title="Coastal cliffs">
    <img src="…" alt="…">
    <h3>Coastal cliffs</h3>
    <a href="…">Learn more</a>
  </div>
  <div data-title="City at dusk">…</div>
  <!-- …one block per slide… -->
</au-carousel>

Each direct child of <au-carousel> is one slide, and gets one pagination dot. Native HTML first; drop in UI Kit components where you need them. The component sizes and snaps the blocks — you style their contents.

Custom Style

Restyle the whole carousel by overriding its --au-carousel-* variables on the host — no shadow-DOM surgery needed. This example uses the .custom-carousel class (defined in demo.css) to swap the dots and buttons to the brand's primary colour and square off the buttons. 

/* demo.css */
.custom-carousel {
  --au-carousel-gap: 1.5rem;
  --au-carousel-dot-color: var(--color-primary-400);
  --au-carousel-dot-current-color: var(--color-primary-600);
  --au-carousel-dot-focus-shadow-color: var(--color-primary-500);
  --au-carousel-button-bg: var(--color-primary-500);
  --au-carousel-button-text-color: var(--color-white);
  --au-carousel-button-radius: 0.5rem;
  --au-carousel-button-focus-shadow-color: var(--color-primary-500);
}
<au-carousel class="custom-carousel"> … </au-carousel>

How to test the accessibility

  • Tab order (dots → content → arrows): Tab reaches the dot group first (one stop; ←/→/Home/End move between dots and jump). Further Tabs go through each slide's link in order — including back with Shift+Tab — and the carousel scrolls to follow your focus. Then the prev/next buttons.
  • Free reading: with a screen reader you can read through every block (forward and back), not only what's on screen. The scroll container is not a focus stop, so there is no "read the whole list at once" dump.
  • Named dots: each dot is labelled by its slide's title, so a screen reader announces e.g. "Forest light" — not "3".
  • Change feedback: arrows, dots and swiping all update a polite live region ("Forest light, item 3 of 6").
  • Reach the end: next/prev and the dots all reach the very last slide; it scrolls to the left edge so the dots line up.
  • Responsive: narrow the window — slides-per-view steps 3 → 2 → 1 via @container.
  • Reduced motion: turn it on in your OS — scrolling jumps instantly.

Slide naming (fallback chain)

Titles are not required, but each dot always gets an accessible name:

  1. an explicit data-title on the slide;
  2. otherwise the slide's own heading (h1–h6) text;
  3. otherwise a positional fallback, e.g. "Item 3 of 6" (from data-item-fallback, translatable). In that case the component also logs a dev-console hint suggesting a title.

Properties

PropertyTypeDescription
currentnumberIndex of the current (left-most) slide. Set it to move the carousel.
const c = document.querySelector('au-carousel');
c.current = 2;         // go to the third slide
c.slideTo(0);          // back to the first
console.log(c.current);

Methods

MethodDescription
slideTo(index)Scroll to index (clamped to range) and make it current.

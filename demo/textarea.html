Accesserty UI Kit Textarea

Attributes

The Accesserty UI Kit textarea text and accessibility attributes:
Name Description
label Visible label text. Used as fallback accessible name when aria-label and aria-labelledby are not set.
placeholder Textarea placeholder text.
aria-label Accessible name passed to the internal textarea.
aria-labelledby Label IDs resolved in the containing document or shadow root; references track inserted and replaced labels.
aria-describedby / aria-invalid Resolve visible help or error text IDs and expose application validation state. Applications supply the message text.

Localized Text Attributes

External label and help text

Describe what you observed. Do not include sensitive information.

Native labels associated with the host supply the name when no internal or explicit label is set. Clicking the label focuses the textarea. An explicit aria-labelledby can reference other visible text. Older engines use plain-text reference fallbacks, not the full accessible-name algorithm; supply a localized aria-label for rich labels there.

Readonly and disabled

Unavailable section

Readonly fields retain their native form value. Disabled fields, including those inside a disabled fieldset, cannot be edited and are omitted from submission. Programmatic value assignment remains available.

CSS Variables

Content-based height is progressive enhancement. Where field-sizing: content is unsupported, native rows and scrolling remain available. Vertical resizing is allowed. The default boundary and focus colors are intended for light backgrounds; recheck contrast when overriding tokens or using a dark surface.

Properties

JavaScript properties on <au-textarea>:
Property Type Description
value string (getter + setter) Get or set current content; native line-break normalization is also used for submission. Property assignment is silent and does not reflect to the value attribute. Setting or removing the value attribute updates current content.
name / required string / boolean (getters + setters) Reflect the submission name and required attribute. An empty name produces no form entry.
disabled boolean (getter + setter) Get or set the disabled state. React-safe: setting to false removes the attribute.
readonly boolean (getter + setter) Get or set the read-only state. 
const ta = document.querySelector('au-textarea');
ta.value = 'Prefilled content';
ta.readonly = true;

focus(options) focuses the internal textarea. Form reset restores the value at first connection, preserves textarea focus and rebinds accessible references. Reset and state restoration do not emit input/change.

Register the component on the client, not through a server-side module import. The Next, Nuxt and Angular fixtures in test/ssr/ cover host hydration and client interaction; the server does not render the internal textarea. Use explicit :value="notes" @input="notes = $event.target.value" for Nuxt SSR. Angular form directives require a value accessor in addition to custom-element schema configuration.

Events

Events dispatched by <au-textarea>:
Event Description
input One notification per native input event. Composed events preserve their identity, trust and composition metadata; non-composed events are bridged once. This includes text entry, paste and composition updates, not every physical key.
change One notification when the native textarea commits a change. Non-composed events are bridged once to the host.

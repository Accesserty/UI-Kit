Accesserty UI Kit Popover

Key Point

  • The global HTML attribute popover handles showing, hiding, the top layer and light dismiss. It adds no semantics: roles, names and descriptions are still yours to write.
  • Choose the type by behavior: auto for menus and panels, manual for toasts and persistent panels, hint for tooltips.
  • Open and close it with Invoker Commands (command / commandfor) or interestfor for hover and focus, without JavaScript.
  • Place it with CSS anchor positioning, and let position-try-fallbacks move it when it would be cut off at the edge of the window, for example when the page is zoomed to 200% or 400%.

<div id="tip" popover="hint" role="tooltip">You can also press Ctrl+S.</div>

WCAG 1.4.13 requires hover and focus content to be dismissible, hoverable and persistent:

  • popover="hint" closes with Esc and on clicking outside. A browser without hint treats it as manual, which neither closes on Esc nor on clicking outside, so this page adds Esc handling in that case.
  • interestfor keeps the tooltip open while the pointer moves onto it. Without interestfor, this page delays hiding and cancels it when the pointer reaches the tooltip.
  • Neither closes on a timer, so the content persists.
  • Add role="tooltip" and aria-describedby yourself, and keep links and buttons out of tooltips: content you can interact with belongs in an auto popover.

Opening the toast while the menu is open closes the menu, because that click lands outside it. This is light dismiss working as specified.

In Chrome 154, a single Esc closes both a tooltip opened by interestfor and the menu it sits in, and moves focus back to the menu button. A tooltip opened by script closes on its own first. To keep WCAG 1.4.13's "dismiss without moving focus", this page gives each open tooltip a CloseWatcher, which takes that first Esc for the tooltip alone.

Staying inside the window with @position-try

Both menus open below their button. Pin the buttons to the bottom of the window and open each one: without a fallback the menu is cut off; with flip-block it opens above instead.

Without position-try-fallbacks I always open below.

Near the bottom edge part of me is cut off.

The browser keeps the original position when nothing fits.

With flip-block I open above when there is no room below.

flip-inline moves me left at the right edge.

My 4px gap flips with me.

.menu {
  position-anchor: --menu-button;
  inset: auto;
  margin: 4px 0 0;
  position-area: bottom span-right;
  position-try-fallbacks: flip-block, flip-inline, flip-block flip-inline;
}
  • Flipping changes the position on screen only. Reading order and Tab order stay the DOM order.
  • After a flip the browser keeps the new position while the popover stays open, so it does not jump while you scroll. Closing and reopening it picks again.
  • When no option fits, the original position is used. Make the first position the most common one.
  • @position-try rules hold only position, inset, margin, size and alignment properties.

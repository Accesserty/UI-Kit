Accesserty UI Kit Pagination

Attributes

The Accesserty UI Kit pagination attributes:
Name Description
data-total Total number of items across all pages.
data-current-page The page number that is currently selected.
data-pager-count How many page buttons to display in the pager group at once.
data-page-size Number of items to display per page.
data-page-size-options Comma-separated or JSON array of available page-size options (e.g. [10,30,50,100]).
data-layout Array or list of controls to show in the fixed component order (e.g. ['total_page','total_items','page_size','first','prev','pages','next','last','jump']).
data-text-total-pages-prefix Text shown before the total pages count (e.g. “Total”).
data-text-page Suffix text for a page number (e.g. “page(s)”).
data-text-total-items-suffix Suffix text for total items count (e.g. “item(s)”).
data-text-per Prefix text for the page-size selector (e.g. “each page”).
data-text-first Label for the “first page” button.
data-text-prev Label for the “previous page” button.
data-text-next Label for the “next page” button.
data-text-last Label for the “last page” button.
data-text-go Prefix text for the “jump to” input (e.g. “go to”).
data-text-goto Visible label for the jump confirmation button (e.g. “Jump”).
data-text-pagination-label Accessible name for the pagination navigation landmark.
data-text-page-size Visually-hidden label for the page-size selector.
data-text-page-announcement Live region message when the current page changes. Supports {page}. 
<au-pagination
  data-text-pagination-label="分頁"
  data-text-page-size="每頁顯示筆數"
  data-text-page-announcement="目前第 {page} 頁">
</au-pagination>

Properties

total, currentPage, pageSize and pagerCount are writable numeric properties backed by their corresponding data-* attributes. Attribute/property updates are silent. Read the properties for normalized effective values: pages clamp to the available range, sizes must be positive safe integers, and pagerCount is capped at 100.

The active page size is always included in the select, even if omitted from the configured options. Invalid array settings use defaults; invalid entries are discarded. Layout selects visible controls in the component's fixed information/navigation/jump order; it does not reorder them.

JavaScript properties on <au-pagination>:
Property Type Description
pageSizeOptions number[] Get or set the available page-size choices as a JavaScript array. Equivalent to the data-page-size-options attribute but accepts an array directly without JSON serialization. 
document.querySelector('au-pagination').pageSizeOptions = [5, 10, 25, 50];
layout string[] Get or set the visible controls as a JavaScript array. Equivalent to the data-layout attribute but accepts an array directly. 
document.querySelector('au-pagination').layout = ['prev', 'pages', 'next'];

Events

Events dispatched by <au-pagination>:
Event Detail Description
page-change number (the new page number) Fired when the user navigates to a different page. Bubbles and is composed.
page-size-change number (the new page size) Fired once after the new size and page 1 are set. No additional page-change event is emitted. Controlled frameworks must update both size and page in this handler. Bubbles and is composed. 
const pagination = document.querySelector('au-pagination');

pagination.addEventListener('page-change', (e) => {
  console.log('Current page:', e.detail);
});

pagination.addEventListener('page-size-change', (e) => {
  console.log('Page size:', e.detail, 'Current page:', pagination.currentPage);
});

Navigation and language updates retain existing controls and focus. When a focused control becomes disabled or is removed, focus moves to the current page or available navigation fallback. Jump accepts whole pages within its range; invalid entries use native browser validation. Page announcements do not certify that asynchronously loaded results have finished loading.

For Next, Nuxt and Angular SSR, register the component only on the client, bind data-current-page/data-page-size, and consume the numeric custom-event details. Servers render the host, not the interactive shadow controls. See test/ssr/ for executable examples. These checks are not a WCAG conformance or screen-reader certification.

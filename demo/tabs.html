Accesserty UI Kit Tabs

This component provides horizontal tabs, keyboard selection and named content panels. Your application still needs meaningful labels, appropriate content, theme contrast and assistive-technology testing. Using the component is not a guarantee of WCAG conformance.

Attribute

The Accesserty UI Kit Tabs tab panel attributes (set on each .au-tab-panel element):
Name Description
label tab name
data-prefix text before label
data-badge text next label
data-affix text after data-badge
id Stable panel ID, preserved unchanged. Missing panel IDs are generated once while managed; tab buttons have separate generated IDs.
label-langLanguage of the generated tab label. Panel content keeps its own language.
Attributes on <au-tabs> for localization:
Name Description
data-text-tab Fallback tab label template when a panel does not provide label. Supports {index}.
data-text-tab-lang Language code applied to generated fallback tab labels.
data-text-badge-label-prefix Accessible label prefix for data-badge.
aria-label / aria-labelledbyName the tab list, preferably using a visible heading. External label IDs resolve in the containing document or shadow root.
selected-indexZero-based declarative selection, including server output. Attribute changes set current selection; user selection does not reflect it.
<au-tabs aria-label="Example sections"
  data-text-tab="頁籤 {index}"
  data-text-tab-lang="zh-Hant-TW"
  data-text-badge-label-prefix="補充資訊：">
  <div class="au-tab-panel" slot="panel" label="Settings" label-lang="en" data-badge="3">Content</div>
</au-tabs>

Properties

JavaScript properties on <au-tabs>:
Property Type Description
selectedIndex number Get or set the zero-based index; an empty group returns -1. Programmatic updates are silent and preserve focus outside the component. Nonnegative integer requests clamp to available panels; invalid requests are ignored. Requests before panels exist apply when panels arrive. 
const tabs = document.querySelector('au-tabs');
// Get current tab index
console.log(tabs.selectedIndex); // 0

// Programmatically select the third tab
tabs.selectedIndex = 2;

Selection follows panel identity when panels are reordered. Removing the selected panel chooses the panel at its previous position, or the last remaining panel. Label, badge and language updates keep the tab button and its focus. Removed panels regain the original attributes still owned by the component.

Events

Events dispatched by <au-tabs>:
Event Detail Description
tab-change { index: number, label: string } One notification when user activation changes selection. Repeated activation, property/attribute writes and structural updates are silent. The label includes the effective fallback text when needed. Bubbles and is composed. 
// Vanilla JS
document.querySelector('au-tabs').addEventListener('tab-change', (e) => {
  console.log('Tab index:', e.detail.index);
  console.log('Tab label:', e.detail.label);
});

// Vue
// <au-tabs @tab-change="onTabChange">

// Angular
// <au-tabs (tab-change)="onTabChange($event)">

// React (ref)
// tabsRef.current.addEventListener('tab-change', handler);

Keyboard and framework integration

Left/Right select visually adjacent tabs with wrapping, mirrored in RTL; Home/End select the first/last tab. Up/Down keep normal page scrolling. Tab follows the native sequence into the active panel and its content; inactive panels are hidden and inert. Panels receive a default Tab stop; an explicit consumer tabindex overrides it. Empty groups use the named tab list as a focus fallback after removal.

Only use this automatic-activation pattern when panel content is already available without a noticeable delay. This component does not implement vertical tabs, delayed/manual activation, or closable-tab commands.

Bind selected-index (or the selectedIndex property after registration) and update your model from tab-change.detail.index. Register only on the client. The Next/Nuxt/Angular fixtures verify server-produced hosts and light-DOM panels, hydration identity, reactive labels and keyboard interaction; they do not server-render the shadow tab buttons or guarantee no-JavaScript tab behavior.

Tab-to-panel relations use native element references. Older engines without that API retain named panels, but lack that relation. Panel names use plain aria-label text because a light-DOM panel cannot reference a button inside a descendant shadow root. This boundary needs assistive-technology verification.

Properties

JavaScript properties on <au-input>:
Property Type Description
value string (getter + setter) Get or set the input value programmatically. Property and attribute updates synchronize the displayed and submitted value, including native type sanitization. Programmatic assignment does not emit an input event.
disabled boolean (getter + setter) Get or set the disabled state. React-safe: el.disabled = false removes the attribute.
required boolean (getter + setter) Get or set the required constraint.
readonly boolean (getter + setter) Get or set the read-only state.
valueAsNumber / valueAsDate number / Date | null (getter + setter) As on a native input: the value as a number for number, range and date-like types (NaN otherwise), or as a Date.
validity / validationMessage / willValidate read-only The field's validation state, as on a native field.
checkValidity() / reportValidity() method Check the field; reportValidity() also shows the message and moves focus to the field.
setCustomValidity(message) method Mark the field invalid with your own message (for example "This address is already registered."); it blocks submission. Pass '' to remove it. The field's own checks, such as required, keep working.
form HTMLFormElement | null (read-only) The form the field belongs to, including through the form attribute. 
const input = document.querySelector('au-input');
input.value = 'Hello';
input.disabled = true;
input.required = false; // removes required attribute

A disabled ancestor fieldset also disables editing and clear actions. Readonly keeps the named value in native form submission but prevents editing, clearing and suggestions. Clearing from the built-in button returns focus to the input. Reset restores the initial value, rebinds accessible references and preserves input focus.

Browser string-state restoration synchronizes non-file input values and validation silently without replacing the initial reset value. Actual history restoration and autofill depend on the browser; callback tests are not proof of password-manager or BFCache support.

Vue and Nuxt: bind with v-model, also in server rendering; with type="number" it gives a number, as on a native input. React: use AuInput with value and onChange. See the README's framework integration.

Events

Events dispatched by <au-input>:
Event Description
input One notification per native input event, including paste and composition updates. Native composed events keep their InputEvent data, inputType, isComposing and trust; non-composed events are bridged once. Clear and suggest APIs emit synthetic input notifications.
change One notification when the native control commits a change (timing depends on input type). Non-composed events are bridged; clear also emits change. Ordinary value assignment and reset are silent. 
document.querySelector('au-input').addEventListener('input', (e) => {
  console.log('Current value:', e.target.value);
});
